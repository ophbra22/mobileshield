## Final versions and concrete fix

Only two requirements change: Requests **2.32.3 → 2.33.0** and python-jose **3.3.0 → 3.5.0**. All other installed distributions in the project environment remain at their pre-task versions, including FastAPI 0.115.6, Starlette 0.41.3, pyasn1 0.6.4 and ecdsa 0.19.2. No framework/provider migration or dependency override was used.

Requests 2.33.0 is the first fixed release for [GHSA-gc5v-m9x4-r6x2 / CVE-2026-25645](https://github.com/psf/requests/security/advisories/GHSA-gc5v-m9x4-r6x2) (Moderate; PYSEC-2026-2275). It also includes the 2.32.4 fix for [GHSA-9hjg-9r4m-mvj7 / CVE-2024-47081](https://github.com/psf/requests/security/advisories/GHSA-9hjg-9r4m-mvj7) (Moderate; PYSEC-2026-1872). The first concerns direct `extract_zipped_paths()` calls and local temp-file substitution; the second concerns malicious URLs and `.netrc` credentials. Application code calls neither Requests nor that extraction helper directly. The static scan path uses a bundled suffix snapshot, and tests independently prohibit Requests, DNS and transport calls. The bump removes the observed Requests/chardet 7.6.0/urllib3 compatibility warning; it does not add ambient network access.

The brief's python-jose 3.4.0 candidate was tested, then rejected on evidence: its published wheel metadata requires `pyasn1>=0.4.1,<0.5.0`. Pip normally downgraded 0.6.4 to 0.4.8, introducing four High advisory matches: [GHSA-jr27-m4p2-rc6r](https://github.com/pyasn1/pyasn1/security/advisories/GHSA-jr27-m4p2-rc6r) (nested ASN.1 recursion; fixed 0.6.3), [GHSA-8ppf-4f7h-5ppj](https://github.com/pyasn1/pyasn1/security/advisories/GHSA-8ppf-4f7h-5ppj) (OID complexity), [GHSA-hm4w-wwcw-mr6r](https://github.com/pyasn1/pyasn1/security/advisories/GHSA-hm4w-wwcw-mr6r) (REAL conversion), and [GHSA-m4p7-r5rc-7g4j](https://github.com/pyasn1/pyasn1/security/advisories/GHSA-m4p7-r5rc-7g4j) (long tags; latter three fixed 0.6.4). These are parser risks, not demonstrated scan exploits. [python-jose 3.5.0](https://github.com/mpdavis/python-jose/releases/tag/3.5.0) removes that upper bound (wheel metadata: `pyasn1>=0.5.0`) and the normal resolver restores 0.6.4. The controller confirmed this evidence-based same-major adjustment. Both candidate installs, metadata and comparisons are retained; no constraint was bypassed.

[python-jose 3.4.0's release notes](https://github.com/mpdavis/python-jose/releases/tag/3.4.0) confirm the original OpenSSH/public-key guard and compressed-JWE fixes, inherited by 3.5.0: GHSA-6c5p-j8vq-pqhj and [GHSA-cjwg-qfpm-7377](https://github.com/advisories/GHSA-cjwg-qfpm-7377) / CVE-2024-33664 / PYSEC-2024-233 (Moderate). The original guard advisory shares aliases with the still-unpatched DER issue below; it must not be counted as an independently cleared alias family.

`SecurityHeadersMiddleware` now chooses its documentation CSP from `request.scope['path']`. A Host such as `testserver/docs?marker=` previously selected the relaxed documentation policy for actual JSON/error routes; a Host with a different apparent path removed the intended docs policy. Routing already uses the ASGI path. Scan rate admission also already uses `scope.get('path')`; all POST body/work admission is path-independent. No TrustedHost configuration or permission change was made.

## Evidence and scope of reachability review

`task11-reachability.json` captures all 12 registered routes, endpoint classes, recursive dependency call names, body-field kinds and source hashes. There are no mounted apps/static directories, `HTTPEndpoint` classes, form body fields or application `.form()`/`.mount()`/`.url_for()` calls. Only `analyze_router` is included. Two scan POST routes and the admin POST route use Pydantic JSON bodies. History and PDF paths return 410. Health/readiness return JSON, and FastAPI's four documentation routes return HTML/OpenAPI JSON. No endpoint returns `FileResponse`.

The admin route's dependencies are admin token, IP allowlist and database; its key generator uses `secrets` and `hmac` SHA256 independently of jose. `resolve_identity()` in `app/auth.py` and `get_current_user()` in `app/db/deps.py` can decode JWTs, and `app/routers/auth.py` can create them, but none is on the registered route/dependency graph. Key/auth routers remain disabled. JWT functions explicitly create HS256 and decode with `algorithms=['HS256']` using `settings.jwt_secret: str`. No application caller imports JWE, performs ECDSA signing/key generation/ECDH, parses asymmetric keys or accepts attacker-provided verification keys. Synthetic tests exercise roundtrip, expiration, wrong keys, prohibited HS384/HS512 and the corrected OpenSSH-format guard. These are compatibility tests, not proof of the contents or strength of a deployment secret; no credentials were inspected.

Public JSON scan requests retain a 131072-byte body cap, 10-second total body-read deadline and 32 concurrent request-work slots. The existing suite verifies streamed bodies, timeout, errors, privacy and cleanup. These bounds supplement the absence of form/file consumers; they are not a substitute for fixing those APIs if introduced. The new Host tests execute the real ASGI application without a network socket and verify JSON/error/docs routing, no-store, response/request IDs, log redaction and unchanged scan rate admission.

The scope-path correction removes the application's sole executable `request.url` consumer. Starlette itself still reconstructs URLs for slash redirects; this patch does not validate Host globally or claim every framework URL behavior is corrected. No application authorization, outbound fetch target, cache key, callback base or log decision uses a reconstructed request URL. URL-derived scan targets come from separately validated input and the guarded transport. Deployment proxy behavior remains an independent release check.
